# UX pass 2: Garage, Cockpit, Ride, Explorer

Follow-up to the Forge Block restyle (all 8 rows of `DESIGN_SYSTEM.md` §5 done). The restyle fixed
the *look*; this pass fixes *structure*: things that are confusing, redundant, or buried.

Read with: [`../DESIGN_SYSTEM.md`](../DESIGN_SYSTEM.md), [`../data-availability.md`](../data-availability.md),
`.cursor/rules/ui-design.mdc`, `.cursor/skills/restyle-screen/SKILL.md`.

## What the data actually supports (checked 2026-10-24)

Everything below is buildable from tables that already exist in `data/local/.../Entities.kt`. No new
sensors are needed.

| Need | Source | Notes |
|---|---|---|
| Position, GPS speed, altitude, bearing at any second | `track_points` (1 Hz) | Altitude is GPS altitude: label it "GPS alt.", not "elevation". |
| Bike speed, odometer, Trip A/B, fuel bars, econ over time | `telemetry_samples` (~every 5 s) | Odo is **integer km**. |
| Odo at start/end of a ride | `rides.odoStartKm`, `rides.odoEndKm`, `ride_segments` | `RideDetail` only exposes `odoEndKm` today. |
| Fractional odo at a moment | `odoStartKm` + GPS distance so far × the odo-vs-GPS factor in `calibration` | Show it as `≈ 12,345.6 km`, labelled "est.". Hide it for `gpsOnly` rides. |
| Fuel-bar drops / refuels during a ride | `fuel_events` (`ts`, `rideId`) | Not in `RideDetail` yet. |
| Stops | `RideDetail.stopLines` (derived) | Need timestamps to mark them on a timeline. |

## Global fix first: double inset

**Problem (seen on Garage, present everywhere):** 20dp screen gutter + 20dp `SectionCard` padding +
nested `CareCard`s inside cards = 40–60dp lost on each side of a ~411dp-wide phone. Content looks
squeezed into a column.

**Fix:**
- `ScreenGutter` 20 → **16dp**. `SectionCard` inner padding 20 → **16dp**.
- **No card inside a card.** Items inside a `SectionCard` are rows separated by hairline dividers
  (new `ListRow` component), not nested surfaces.
- A `BlockTile` that would sit alone in a row spans full width (the half-width "PAIR THE BIKE" tile
  leaves a dead hole on the right).
- Forms don't live inline on a hub screen. They go into a bottom sheet or their own screen.

## New shared components (add to `DESIGN_SYSTEM.md` §4 and build in `ui/components/`)

| Component | What | Used by |
|---|---|---|
| `ListRow` | 56–64dp row: leading icon tile (40dp) or status dot, title + subtitle, trailing value / chevron / chip. Hairline divider between rows in a `SectionCard`. | Garage menu, Documents, Service, Settings, Explorer rides |
| `ForgeSheet` | `ModalBottomSheet` styled with `Surface`, `ShapeXl` top corners, drag handle, Anton `headlineSmall` title, sticky Lime primary button at the bottom. | All add/edit forms, merge review |
| `DateField` | Read-only field that opens a Material 3 `DatePickerDialog` themed to Forge Block. Replaces every "yyyy-MM-dd" text field. | Documents, Service |
| `StatusChip` | Small pill: `OK` (Lime outline), `DUE SOON` (BlockYellow fill), `OVERDUE` (Danger fill), `NO EXPIRY` (Stroke). Text in `labelSmall`. | Documents, Service, Garage attention strip |
| `DueMeter` | Progress pill showing "used vs interval" for km *and/or* days, whichever is closer to due. Fill colour follows status. | Service plans, Cockpit service card |
| `MonthSwitcher` | `‹  OCTOBER 2026  ›` with Anton month, chevron `ChunkyIconButton`s; tap the label for a month/year picker. | Explorer, Fuel log |
| `InsightPager` | Horizontal pager of equal-height insight cards with a dot indicator (as in `more-menu.jpeg` promo strip). | Explorer patterns, Cockpit |
| `RideReplay` | Map + speed graph + moment card, all driven by one scrub position. See the Ride section. | Ride detail, Ride screen (compact) |

## 1. Garage: a hub plus separate screens

**Today:** one ~870-line scrolling page: profile card, a half-width pair tile, an icon grid whose
tiles just *scroll down the same page*, then always-open forms for Documents (5 fields + 3 buttons),
Maintenance plans (7 fields), Service history, Ride & safety, Fuel, Cluster nav and Permissions.
`yyyy-MM-dd` text fields for dates.

**New structure:**

```
Garage (hub)
├── Bike card         photo · name · connection chip · StatTriple(Odo, Trip A, Trip B) · fuel bars
├── Pair banner       full-width Mint block, only when not paired, pair action inline
├── Needs attention   InsightPager of overdue/due-soon docs & plans (Coral/Yellow), hidden when empty
└── SectionCard "BIKE" of ListRows (not icon grid — every row shows live status):
      Fuel log      → existing "fuel" route        trailing: "38.2 km/l est."
      Documents     → NEW garage/documents         trailing: "1 expiring" StatusChip
      Service       → NEW garage/service           trailing: "Oil in 420 km"
      Settings      → NEW garage/settings          trailing: chevron
      Transfer      → existing "transfer" route    trailing: chevron
```

The MAC address moves to Settings → Bike. The profile card stops listing 5 text lines.

### 1a. Documents screen (`garage/documents`)
- `ForgeTopBar` "Documents" + Lime "Add" compact button.
- Filter `PillChipRow`: All · RC · Insurance · PUC · Warranty · Invoice · Other.
- An **expiry timeline** at the top when any doc has an expiry: a horizontal strip of the next 12
  months with dots for each expiry. It answers "what expires next?" at a glance.
- List of `ListRow`s: kind icon, title, number, `StatusChip` + "expires in 23 days".
- Tap → detail sheet: file preview (image thumbnail / PDF icon → open), number with a copy
  button, expiry, note, Edit / Delete (Danger `ChunkyDialog`).
- Add/edit → `ForgeSheet` with kind chips, title, number, `DateField` expiry, note, attach file.
- `EmptyState` "NO PAPERS YET": "RC, insurance, PUC — keep them where the bike is."
- Optional: "Show at checkpost" button that opens RC + insurance + PUC files full-screen at max
  brightness.

### 1b. Service screen (`garage/service`)
- `ForgeTopBar` "Service" + Lime "Log service" button.
- `PillChip` tabs: **Plans** | **History**.
- **Plans:** one card per plan with a `DueMeter` from current odo / today ("Oil · 2,580 / 3,000 km
  · due in 420 km"), `StatusChip`, and a "Mark done" action that pre-fills the log sheet.
  "Add plan" → `ForgeSheet` (km interval, day interval, due date, last done odo + `DateField`).

`GarageViewModel` split into `GarageViewModel` (hub), `DocumentsViewModel`, `ServiceViewModel`,

## 2. Cockpit: a light restructure, not a rewrite

**Why it feels confusing today:**
1. **Connection state is said 4 times:** the status-bar pill, the hero card "Not connected", the Setup tile
   badge, and the warnings card.
2. **Two tiles duplicate the bottom nav:** "Garage" and "Ride stats" open tabs that are already one
   tap away, and they take the biggest space.
3. **The main action comes last:** "Start ride" sits at the bottom, below the fold.
4. **The readiness radial floats** between the hero and bento, with no label saying what it scores.
5. **Too many loud things compete:** hero, radial, 4 pastel blocks and warnings, with no reading order.

**New order (top → bottom), reusing existing components:**

```
1. Hero card          bike art · name · connection chip (the ONLY place connection is shown)
                      + readiness verdict as the screen's single Anton shout ("READY TO RIDE" /
                      "CHECK 2 THINGS") with the small score ring beside it. Tap → readiness breakdown sheet.
2. Primary CTA        full-width Coral ChunkyButton "START RIDE" (→ "RESUME RIDE" when paused,
                      "VIEW LIVE RIDE" when live)
3. Right now          one row of 3 StatPills: Fuel bars + range est. · Odo · Today km
4. Heads up           only when warnings exist: compact SectionCard of ListRows, each with a fix action
5. Context            InsightPager, max 3 cards, only those with data:
                        Last ride (Lavender, mini track + km/time → ride detail)
                        Service due (Yellow, DueMeter → Service screen)
                        Parked here (Mint, mini map + "2h ago" → Maps intent)
```

**Removed:** the `CockpitStatusBar` row (merged into hero + Right now), the Garage tile, the Ride stats
tile, and the Setup tile. Setup becomes a "Heads up" row when something's missing.

**Acceptance:** above the fold on a 411×891dp phone you see the hero, the CTA and Right now.
Connection appears once. `Readiness.kt` logic is unchanged and `ReadinessCalculatorTest` passes.

## 3. Ride: replay, odo, and less clutter

### Problems
- **The period selector does nothing useful:** "Today / 7 days / Month" cycles a headline while the
  `StatTriple` right below already shows all three.
- **Speed and Route are separate tabs,** so you can't see *where* you were at *what* speed. The
  detail pane already shares a `selectedTs` between them, but the tabs hide one from the other.
- **No moment context:** no clock time, minutes into the ride, distance so far, or odo at a point.
- **Ride detail only shows the end odo.**

### 3a. Data: `RideMoment` (TDD, pure Kotlin)
A pure function in `core/ride` (unit-tested):

```kotlin
data class RideMoment(
    val ts: Long,                 // epoch ms
    val clock: LocalTime,         // "17:42"
    val sinceStartSec: Int,       // "+38:12"
    val distanceKm: Double,       // GPS distance so far
    val remainingKm: Double,
    val odoEstKm: Double?,        // odoStart + distance × odoGpsFactor; null for gpsOnly
    val speedKmh: Int?,           // bike speed if a sample is within 6 s, else GPS speed
    val speedSource: SpeedSource,
    val altitudeM: Double?,       // GPS alt.
    val fuelBars: Int?,           // last telemetry sample at or before ts
    val position: GpsFix?,
    val nearestEvent: RideEvent?, // stop / fuel drop / refuel / max speed within ±30 s
)
object RideTimeline {
    fun build(track, speeds, telemetry, fuelEvents, stops, odoStartKm, odoGpsFactor): RideTimeline
    fun at(ts: Long): RideMoment          // O(log n) via binary search on precomputed cumulative distance
    fun atDistance(km: Double): RideMoment
}
```

Tests to cover: interpolation between fixes, a GPS gap (hold the last value, don't invent),
`gpsOnly` → `odoEstKm == null`, before-start/after-end clamping, the bike-vs-GPS speed fallback, and
the odo estimate never decreasing.

`RideDetail` gains `odoStartKm`, `timeline: RideTimeline`, and `events: List<RideEvent>` (stops with
ts, fuel drops/refuels, max-speed point).

### 3b. Component: `RideReplay`
One component, one scrub state, three synced views:

```
┌───────────────────────────────────────┐
│  MAP (OSM tiles, existing TrackPath)  │  route coloured by speed band
│   ● marker at the current moment      │  (band colours = histogram colours)
│   start ◉ / end ⚑ / stop ▮ / fuel ⛽  │  km ticks every 5 km
├───────────────────────────────────────┤
│  MOMENT CARD (SurfaceRaised, chunky)  │
│   62 km/h      17:42 · +38:12         │  speed in NumberLarge, tinted by band
│   18.4 km of 47 · odo ≈ 12,358.4 est. │
│   ⛽ 4 bars · GPS alt. 912 m · "Stop" │  event chip when near one
├───────────────────────────────────────┤
│  SPEED GRAPH (scrubbable)             │  drag anywhere → cursor + haptic tick per km
│   ▁▃▆█▆▃▁  stops as grey gaps,        │  event pins on top edge, tap pin → jump
│   fuel pins, max-speed pin            │  x-axis toggle: TIME | DISTANCE
│  ▶ play  1× 4× 16×        ⟲ reset     │  replay animates marker + cursor
└───────────────────────────────────────┘
```

Interaction rules:
- **One state:** `scrubTs` lives in the composable's state holder. Dragging the graph, tapping the map
  (nearest point), tapping an event pin, and tapping a "What stood out" insight all set it.
- **Play** advances `scrubTs` at 1×/4×/16× ride time (16× ≈ a 1 h ride in ~4 min) and pauses on
  drag. Honour reduced motion: no autoplay, and the marker jumps instead of gliding.
- **Haptics:** a light tick each time the cursor crosses a whole km, and a stronger one on an event.
- **Graph modes:** Speed (default) · GPS alt. · Fuel bars, using `PillChip`s above the graph.
- **The x-axis** toggles between time and distance (distance mode squeezes stops out, so the shape of the
  road shows).
- **Performance:** downsample for drawing (existing `TrackPlot.downsample`), but compute moments
  from full-resolution data. Map tiles load once per ride.

```
ForgeTopBar  "Sun 19 Oct · Morning ride"      [share]
```

### 3d. Ride screen (archive) simplified

**Today:** month/day chips (duplicating the calendar) → a merge-suggestions card with 2 huge
buttons per suggestion → Streak → Repeat routes → Weekdays → Time of day → 2026 Recap → Calendar
→ Story → Rides. Ten blocks, and the most useful one (the calendar) is buried.

**New structure:**

```

Month         StatTriple: km · rides · moving time  (+ "vs Sep +12%" caption)
Calendar      RideCalendar as the hero: day cells shaded by km (heat map), today ringed,

              "2 outings look split · Review" → ForgeSheet listing suggestions, each with
              Merge (Lime) / Not one trip (Outline) / view day

              Longest ride · Month map (all tracks overlaid)
```

**Removed:** the Month/day `PillChipRow`, the standalone Streak card (it becomes a pill), the always-open
merge cards, and the separate Weekday / Time-of-day / Recap / Repeat-routes cards (they move into the
pager or the recap screen).

### 4a. Year recap screen (`explorer/recap/{year}`), new
A story-style vertical pager, one big fact per page, each in a block colour: total km (with
"that's Chennai → Delhi ×N"), rides, longest ride (mini map), top speed (bike), busiest month,
favourite repeat route, fuel used / ₹ spent (when logged), and a "share" page that renders a share
card. Uses existing rollups; nothing new is recorded.

**Acceptance:** with a typical month, calendar + month stats + first rides are visible within ~1.5
screens; no duplicate date selector; merge suggestions are never more than one row on the page.

## 5. Other improvements (optional, pick any)

Ranked by value for effort. All are within the data rules.

1. **Speed-coloured route everywhere** (ride list thumbnails, share card): this falls out of 3b.
2. **"Ride again" on repeat routes:** open Google Maps directions to the end point of a repeat route.
3. **Fuel log ↔ ride link:** a fill-up row shows which ride it happened on and jumps into that
   ride's replay at the refuel moment (`fuel_events.rideId` + `ts`).
4. **Home-screen widget** (Glance), like the reference's "Add a home widget" card: fuel bars, range est.,
   next service, last ride km. Read-only, from the same repositories.
5. **Checkpost mode** for documents (see 1a).
6. **Service reminders as notifications** when a plan crosses "due soon" by odo, not only by date.
7. **Calibration health in Settings:** the odo-vs-GPS factor and km-per-bar curve shown plainly, with
   "reset calibration".

Not recommended: anything that implies RPM, gear, temps, or engine faults (golden rule).
