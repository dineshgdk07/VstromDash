# Journey → cluster a531 Implementation Plan (Plan 7 of v1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans.

**Goal:** When Google Maps is navigating, parse its notification, encode a531, and write it to the bike; Journey shows listener status + live preview; HUD shows the current turn. No Maps SDK, no in-app map, no idle-clock a531.

**Architecture:** Pure `core:nav` (guesser, Mappls→cluster table, distance/ETA normalize, `MapsNavSource`). App `NotificationCaptureService` parses Maps extras → `MapsNavSource`. `BikeBridgeService` enqueues NAV (and re-asserts every 2s past FrameWriter dedup). Honest copy: arrows are inferred from instruction text; wrong-arrow risk exists.

**Tech Stack:** Existing protocol `NavFrame`, `FrameWriter.Priority.NAV`, NotificationListenerService. JUnit in `core:nav`.

**Spec:** Design spec §5 a531 + v1 Journey. REDLINE `NavFrame` / `ParsedNavData` / `MapplsIdGuesser` / `ManeuverMap.mapplsIdToClusterByte` (Gixxer/V-Strom default branch, not Burgman).

## Global Constraints

- capture-pipeline, JDK 17, Gradle 8.12 fallback.
- a531 `status='1'` while navigating so the cluster draws the arrow.
- Do not ship bitmap-hash / ManeuverClassifier (wrong-arrow + complexity).
- `arrive`/`destination` must beat the `"head "` catch-all.
- One commit per task.
